Recloud ERP Architecture

A comprehensive overview of the system from inception to current deployment. Covers architecture, completed modules, challenges, and roadmaps.

Core Technologies & System Architecture

Languages & Frameworks

  • React.js: Core frontend framework for the Single Page Application (SPA).
  • Tailwind CSS: Rapid UI styling and responsive design.
  • Firebase Firestore: NoSQL cloud database for real-time data syncing and multi-tenancy storage.
  • jsPDF: For automated PDF document generation (Receipts, Invoices, Purchase Orders).

Structural Integrity

The system utilizes a central orchestrator approach. The App.jsx file acts as the "Brain", fetching all data collections via a massive Promise.all execution upon login. This ensures all modules (HR, CRM, POS) have instant, synchronous access to data without loading spinners when switching tabs.

It relies heavily on Multi-tenancy (data isolated by Organization IDs) and Role-Based Access Control (RBAC), restricting views based on employee roles and branch assignments.

Completed Stages & Modules

Stage 1: Foundation, Admin, & Human Resources

Phase 1 Complete

Transitioning from the legacy G4mg-Adamz logic to a scalable cloud ecosystem. Built the structural backbone for users, permissions, and organization data.

Module Features

  • Global Authentication: Login screen validating Organization ID and Employee credentials.
  • Employee Directory: Full roster management, role assignments, and initial avatar generation.
  • Branch/Location Management: Ability to create distinct store locations to bind employees and stock to specific physical places.
  • Recruitment System: Public-facing careers page and applicant tracking system (ATS).

Challenges & Resolutions

  • Challenge: Employees needed access to only their specific store's data.
  • Resolution: Implemented a warehouseId variable in the employee profile. All subsequent queries check if a user is an Admin; if not, it strictly filters data to match their warehouseId.

Stage 1.5: CRM (Customer Relationship Management)

Completed

Developed a robust client tracking and sales pipeline system for B2B and retail tracking.

Module Features

  • Customer Database: Add, edit, and track customer contact information.
  • Deals Pipeline: Kanban-style drag-and-drop board (Lead -> Negotiation -> Won -> Lost).
  • Invoicing: Generate and track invoices, log payment statuses, and print standard A4 PDF invoices.

Challenges & Resolutions

  • Challenge: Integrating CRM with POS later in the build.
  • Resolution: Structured the customers Firestore collection so that the POS module can read directly from the CRM, allowing cashiers to select existing CRM clients at checkout.

Stage 2: Point of Sale (POS) & Inventory Control

Phase 2 Complete

The most complex phase: handling live financial transactions, stock deductions, and cashier workflows.

Inventory Features

  • Product Catalog: Categorization (e.g., Pharmaceuticals, Beverages) with image support.
  • Supplier Network: Database of suppliers assigned to specific branches.
  • Purchase Orders (LPOs): System to generate formal Local Purchase Orders as PDFs to send to suppliers.
  • Stock Distribution: Track inventory levels uniquely per warehouse branch.

POS Features

  • Fast Checkout UI: Image grid, category filters, and smart search bar.
  • Hold System: Pause a transaction queue and start a new one if a customer is delayed.
  • Taxes & Discounts: Manual percentage input per transaction.
  • Receipt Engine: Downloads an 80mm/58mm thermal-printer ready PDF on sale completion.
  • Shift Management (Best Practice): Cashiers must declare opening floats (cash in drawer) at the start of shifts and generate Z-reports (Expected vs Actual counts) at shift end to combat fraud.
  • Loyalty & Split Payments: Tracks points globally based on standardized currency values. Supports combined card/cash checkout.
  • Barcode Listeners: Implemented global window listeners to instantly capture 1D/2D USB barcode scanner inputs without requiring focus on a specific input field.

CRM & B2B Best Practices Added

  • Stuck Deal Alerts: Deals inactive for > 7 days flag visually.
  • Activity Logging: Categorized logs (Calls, Emails, Meetings) with metadata rather than plain notes.
  • B2B Wholesale Portal: B2B routing system for distributors. Orders placed enter a "Pending B2B Orders" queue in the Inventory module for admin approval. Built-in credit limits prevent ordering if thresholds are surpassed.

Challenges, Questions & Solutions

  • Q: Can customer names be detected directly from ATM cards?
    Web applications cannot natively read encrypted physical card chips. Solution: We built a Dual-Flow system. We provided a manual button for traditional bank POS machines, and a "Sync Smart Terminal" button to interface with API-enabled machines (like Paystack Terminal) for automated data retrieval.
  • Q: How to handle global barcode scanning when typing?
    Solution: The barcode event listener checks if the active DOM element is an `INPUT` or `TEXTAREA`. If it is, it ignores the scan to allow normal typing. If not, it rapidly concatenates keystrokes occurring within 20ms of each other (human typing is slower) and resolves it as a barcode SKU search.
  • Challenge: Stock Race Conditions during checkout.
    Solution: Utilized Firebase writeBatch. A sale record and a stock deduction happen atomically. If the stock deduction fails, the sale cancels, ensuring inventory levels are never compromised.

Hardware Integration Guide

1. Printing Capabilities

The system generates standard A4 PDFs for Invoices/LPOs, and 80mm condensed PDFs for the POS. Required hardware:

  • 80mm Thermal Receipt Printer (USB/Bluetooth) - e.g., Xprinter.
  • Standard Office Printer (For Invoices/LPOs).

2. Payment Terminals

Based on the checkout flow you choose:

  • Standard Setup: Regular Bank POS (Moniepoint, Opay). Cashier uses "Complete Sale (Manual)".
  • Advanced Setup: Smart POS (Paystack/Square). Uses the "Sync Smart Terminal" feature to push prices to the machine automatically over WiFi.
